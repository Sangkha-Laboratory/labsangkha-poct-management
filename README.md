# Sangkha Hospital DTX Management System
### ระบบบริหารจัดการเครื่องตรวจวัดน้ำตาลปลายนิ้ว (DTX)
**กลุ่มงานเทคนิคการแพทย์ โรงพยาบาลสังขะ**

ระบบบริหารจัดการ ตรวจสอบคุณภาพ และบำรุงรักษาเครื่องตรวจวัดน้ำตาลปลายนิ้ว (DTX) ของโรงพยาบาลสังขะ เพื่อช่วยให้ทีมเครื่องมือแพทย์และบุคลากรทางห้องปฏิบัติการสามารถดูแล ควมคุมคุณภาพ และติดตามการใช้งานเครื่องวัดน้ำตาลในแต่ละตึก/หน่วยงานได้อย่างมีประสิทธิภาพสูงสุด

---

## 🌟 ฟีเจอร์หลักของระบบ (Key Features)

### 1. ระบบแจ้งซ่อมและวินิจฉัยบำรุงรักษา (Repair & Maintenance)
* **แจ้งซ่อมเครื่องชำรุดออนไลน์**: บุคลากรประจำตึกสามารถส่งข้อมูลเครื่องที่ชำรุดพร้อมระบุอาการขัดข้องได้ทันที
* **ขอเครื่องสำรองใช้ชั่วคราว**: มีฟังก์ชันตัวเลือกให้ติ๊กขอเบิกเครื่องสำรองใช้ชั่วคราวระหว่างรอเครื่องหลักซ่อมแซม (ในกรณีที่ตึกไม่มีเครื่องสำรองใช้งาน)
* **บันทึกผลการตรวจสอบ (Checklist & Diagnosis)**: เจ้าหน้าที่เทคนิคห้องแลปสามารถลงบันทึกการตรวจเช็คสภาพเครื่อง เช่น ความสะอาด, ปุ่มกด, หน้าจอแสดงผล, การตรวจสอบแถบควบคุมคุณภาพ และลงบันทึกผลการวินิจฉัย/ซ่อมบำรุง
* **พิมพ์ใบนำส่งซ่อม (Printable PDF/Form)**: ออกแบบหน้าเอกสารแบบฟอร์มส่งซ่อมที่จัดเลย์เอาต์สวยงามพร้อมสำหรับพิมพ์ลงกระดาษจริงได้ทันที

### 2. ระบบขอเบิกอุปกรณ์และวัสดุ (Request Supply)
* **ส่งคำขอเบิกออนไลน์**: สำหรับขอเบิกอุปกรณ์ทางการแพทย์และวัสดุสิ้นเปลืองสำหรับงาน DTX เช่น แผ่นตรวจ (Test Strip), เข็มเจาะ (Lancet), น้ำยาควบคุม (Control Solution) หรือแบตเตอรี่สำรอง
* **ติดตามสถานะคงคลัง**: มีแดชบอร์ดบริหารจัดการคลังวัสดุและปริมาณการเบิกจ่ายของแต่ละหน่วยงาน

### 3. ระบบควบคุมคุณภาพ (QC 3 Level & EQA)
* **วิเคราะห์คุณภาพแลป (QC 3 Level)**: บันทึกและวิเคราะห์ผลทดสอบแถบควบคุมคุณภาพแยกเป็น 3 ระดับ (Low, Normal, High) เพื่อความแม่นยำในการรักษา
* **การประเมินภายนอก (EQA)**: บันทึกและติดตามผลการส่งตรวจประเมินคุณภาพจากสถาบันภายนอก

### 4. ระบบแจ้งเตือนผ่าน LINE Notify (LINE Notifications)
* **Real-time Alert**: รองรับการเชื่อมต่อกับ LINE API เพื่อยิงแจ้งเตือนเข้ากลุ่มไลน์ทีมเทคนิคการแพทย์ทันทีที่มีการกดส่งเรื่องแจ้งซ่อม หรือส่งคำขอเบิกใหม่ ทำให้ไม่พลาดทุกกรณีเร่งด่วน

## 🚀 วิธีการติดตั้งและเริ่มใช้งาน (Getting Started)

### 1. การเตรียมสภาพแวดล้อม (Prerequisites)
ตรวจสอบให้แน่ใจว่าเครื่องของคุณติดตั้ง **Node.js** (เวอร์ชัน 18 ขึ้นไป) แล้ว

### 2. การติดตั้งโปรเจกต์
ดาวน์โหลดหรือโคลนโปรเจกต์มายังเครื่องคอมพิวเตอร์ของคุณ จากนั้นรันคำสั่งเพื่อติดตั้ง Dependency ทั้งหมด:
```bash
npm install
```

### 3. เริ่มรันเซิร์ฟเวอร์สำหรับพัฒนา (Development Mode)
รันคำสั่งด้านล่างเพื่อเริ่มเซิร์ฟเวอร์ทดสอบในเครื่องคอมพิวเตอร์:
```bash
npm run dev
```
ระบบจะรันผ่านพอร์ตที่กำหนด (เช่น `http://localhost:3000`) คุณสามารถเปิดเบราว์เซอร์เพื่อเข้าดูโปรเจกต์ได้ทันที

### 4. การทดสอบความถูกต้องและการตรวจไวยากรณ์ (Linting)
คุณสามารถตรวจสอบข้อผิดพลาดทางไวยากรณ์และความเข้ากันได้ของโค้ดด้วยคำสั่ง:
```bash
npm run lint
```

### 5. การคอมไพล์โปรเจกต์สำหรับใช้งานจริง (Production Build)
สร้างไฟล์พร้อมใช้งานสำหรับขึ้นโปรดักชันด้วยคำสั่ง:
```bash
npm run build
```
ไฟล์ที่ผ่านการคอมไพล์แล้วจะถูกจัดเก็บไว้ในโฟลเดอร์ `/dist` สำหรับนำไปโฮสต์ต่อบนคลาวด์หรือเว็บเซิร์ฟเวอร์ทั่วไป เช่น Static Web Hosting, Firebase Hosting หรือ Cloud Run

## 📝 โครงสร้างโฟลเดอร์สำคัญ (Key Directories)
```text
├── .github/              # GitHub Actions Workflows
├── src/
│   ├── components/       # คอมโพเนนต์ UI หลัก (LandingPage, RepairManagement, PrintForm, ฯลฯ)
│   ├── types.ts          # ไฟล์ประกาศประเภทข้อมูลหลัก (TypeScript Interfaces)
│   ├── mockData.ts       # ข้อมูลจำลองสำหรับทดสอบระบบในเบื้องต้น
│   ├── App.tsx           # หน้าควบคุมเส้นทางและสวิตช์ผู้ใช้/แอดมิน
│   ├── index.css         # ไฟล์ CSS สไตล์ลิ่งหลัก (Tailwind CSS)
│   └── main.tsx          # จุดเริ่มต้นรันไทม์ React
├── .gitignore            # กำหนดไฟล์ที่ไม่พุชขึ้น Git (ละเว้นพวก API keys, build logs, และ metadata)
├── package.json          # จัดการ Dependency และ Scripts การรันระบบ
└── vite.config.ts        # การตั้งค่าการคอมไพล์ของ Vite
```
